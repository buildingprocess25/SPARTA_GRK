## Finding 1 — Dashboard landing-page KPIs are still mock data presented as live (HIGH)

**Rule:** R-17 (Data & Numbers) / R-38 (Real Content or Honest Placeholder) — Hard Gate.

**Where:** `src/components/EmisiResumeTab.jsx` (the first screen every user sees after login), KPI cards at lines ~205–238 ("Net Emissions (Bersih)", "Emisi Kotor (Scope 1 & 2)", "Total Offset (Pengurang)", "Total Penghematan Biaya"), and the `MainScope2Bridge` call at line ~197 (`scope1Ton={scope1.summary.totalEmissionCO2e}`).

**Why it's a violation:** these numbers come from `resumeKPI`, computed in `src/context/SustainabilityContext.jsx:186` from `scope1.summary`, `scope2.summary`, `pltsData.summary`, `waterData.summary` — all seeded from the static mock dataset in `src/data/sustainabilityData.js`, not from the real database. This was already confirmed earlier in this project's own work: the individual Scope 1, Scope 2, PLTS, and Water Recycle tabs were each separately rewired to real API data (`/api/scope1`, `/api/water-recycle`, `/api/emissions`), but `SustainabilityContext`'s top-level state was never replaced, so the landing dashboard — the number a reader trusts first — is still invented.

**Fix:** wire `EmisiResumeTab.jsx`'s KPI row (and the `MainScope2Bridge`/`MainScope1Bridge` props that still read from context) to the same real endpoints the individual tabs already use, the same way Scope 1, Water Recycle, and PLTS were done. Until fixed, the numbers should at minimum be visibly labeled as placeholder (R-38) rather than shown as live figures.

## Finding 4 — Scattered `backdrop-blur` on floating overlays, no written purpose on record (LOW)

**Rule:** R-10 (Glassmorphism) — Purpose-Gate.

**Where:** ~7 instances across unrelated components — Recharts tooltip containers (`PLTSAnalyticsSection.jsx` x3, `TabProductionTarget.jsx`, `TabSystemPerformancePr.jsx`), a sticky form action bar (`CalculatorEntryForm.jsx:162`), and a skeleton loader (`PLTSDashboardSkeletons.jsx:9`).

**Assessment:** these are not navbar/card/sidebar-wide glassmorphism (the pattern R-10 actually targets); each is an isolated floating element (a chart tooltip, a sticky toolbar, a loading skeleton) using semi-opacity + blur for legibility over chart/page content behind it, which is a defensible purpose. Modal/drawer backdrop scrims in `Header.jsx`, `Sidebar.jsx`, and `BaseModal.jsx` were checked separately and are a different, standard pattern (dimming behind an overlay) — not a violation.

**Fix:** optional. If kept, a one-line comment at each site ("blur so tooltip text stays legible over chart data") satisfies the Purpose-Gate requirement. No removal needed unless you'd rather simplify.
